## 1. Overview & Vendor Management Strategy

Axis LinkUp integrates specialized cloud platform-as-a-service (PaaS) providers to deliver identity, real-time messaging, binary asset management, database clustering, and notification delivery. 

This document defines the configuration, security baselines, region selection, and institutional prerequisites for each external service.

---

## 2. Service Deep Dives & Configuration Baselines

### 2.1 Clerk (Identity & User Management)
- **Service Role:** Identity Provider (IdP), user credential vault, session token generator, and TOTP Multi-Factor Authentication enforcer.
- **Security Baseline:**
  - Enforce TOTP Authenticator app requirement for all `admin` and `super_admin` accounts.
  - User roles stored strictly in `publicMetadata` (write-only via backend secret key).
  - Session cookies configured as `HttpOnly`, `SameSite=Strict`, `Secure`.
- **Webhook Integration:**
  - Endpoint: `https://linkup.axiscolleges.in/api/webhooks/clerk`
  - Events Subscribed: `user.created`, `user.updated`, `user.deleted`
  - Verification: Mandatory cryptographic signature verification via `svix`.
- **Institutional Verification Item:**
  - Determine whether Axis Institute requires Single Sign-On (SSO) integration with Google Workspace for Education or Microsoft 365 (`@axiscolleges.in`) for Phase 2.

---

### 2.2 MongoDB Atlas (Database Engine)
- **Service Role:** Primary document database cluster.
- **Deployment Specifications:**
  - **Provider & Region:** AWS Mumbai (`ap-south-1`).
  - **Legal Compliance:** Mandatory Indian data residency under the **Digital Personal Data Protection (DPDP) Act, 2023**.
  - **Cluster Tier:** Minimum M10 Dedicated Cluster (provides dedicated RAM, CPU burst capacity, and automated snapshots).
- **Network Security & Access:**
  - Database access restricted via SCRAM-SHA-256 user authentication with strict role privileges.
  - Dynamic Vercel Serverless IPs handled via MongoDB Atlas IP Access List (configured with secure credentials and TLS 1.3 encryption).
- **Backup & Retention Policy:**
  - Automated continuous backups with Point-in-Time Recovery (PITR) enabled.
  - Daily snapshot retention for 30 days.

---

### 2.3 Ably Realtime (Real-Time Broker)
- **Service Role:** External stateful WebSocket connection broker and pub/sub message distributor.
- **Architectural Implementation:**
  - Decouples stateless Vercel Serverless compute from stateful client WebSockets.
  - Web clients establish long-lived connections directly to Ably edge endpoints.
  - Next.js Server Actions publish messages statelessly via the Ably REST API (`ably.rest`).
- **Authorization & Token Minting:**
  - Clients never receive master API keys.
  - Ephemeral token requests are minted dynamically via `/api/realtime/token`, granting capability to subscribe only to enrolled course channels (`course:CS301:chat`) and private user streams (`user:101:notifications`).
- **Emergency Mode (MOD-16):**
  - High-priority blast to `broadcast:global:emergency` triggers instant full-screen modal overlays across all active campus viewports in `<100ms`.

---

### 2.4 Cloudinary (Media & Document Storage)
- **Service Role:** Binary asset repository, image transformation engine, and secure document distributor.
- **Direct Client Upload Architecture:**
  - Clients upload files directly to Cloudinary using HMAC-SHA256 signed upload presets generated by `/api/storage/signature`.
  - Bypasses Vercel's 4.5MB serverless payload limit, supporting up to 25MB assignments and 50MB lecture slides.
- **Privacy & Document Protection:**
  - **Tier 1 (Public):** User avatars delivered via global CDN with automatic facial cropping and WebP conversion.
  - **Tier 2 (Authenticated):** Lecture notes and syllabus PDFs delivered to enrolled course members.
  - **Tier 3 (Private):** Student assignment submissions and medical proof slips stored as `private` assets. Accessible **exclusively via 15-minute time-limited signed delivery URLs** minted by authorized faculty or admins.

---

### 2.5 Resend (Transactional Email Delivery)
- **Service Role:** Transactional email gateway for critical institutional alerts, password resets, ticket status updates, and invitations.
- **Template Architecture:**
  - Templates authored in type-safe React components using `@react-email/components`.
- **Domain Verification Prerequisites:**
  - Sending Domain: `notifications.axiscolleges.in` or `linkup.axiscolleges.in`.
  - Axis Institute IT must add DNS records:
    * `TXT` record for SPF verification.
    * `CNAME` records for DKIM public key signing.
    * `TXT` record for DMARC policy enforcement.

---

### 2.6 Firebase Cloud Messaging (FCM — Scheduled for Phase 2)
- **Service Role:** Background Web Push notification delivery to student mobile devices and desktop browsers when the web app is closed.
- **Prerequisites for Activation (Phase 2):**
  - Registration of root service worker: `public/firebase-messaging-sw.js`.
  - Generation of VAPID Web Push key pair in Firebase Console.
  - User opt-in permission prompt integrated into the student notification drawer.

---

### 2.7 Vercel (Edge Ingress & Serverless Hosting)
- **Service Role:** Application build pipeline, global Edge CDN, Edge Middleware execution, and Serverless Function compute.
- **Production Configuration:**
  - Custom Domain: `linkup.axiscolleges.in` with automatic Let's Encrypt TLS/SSL certificate renewal.
  - Edge Middleware (`middleware.ts`) decrypts Clerk session tokens and enforces role access boundaries in `<10ms` before serverless functions execute.
  - Zero-downtime atomic deployments on every merged pull request.
